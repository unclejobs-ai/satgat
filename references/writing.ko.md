# 삿갓 한국어 문서 작성 레퍼런스

삿갓의 문장은 단정하고 구체적이어야 한다. 격조는 어려운 단어나 상징 문자에서 나오지 않는다. 정확한 사실, 짧은 호흡, 안정된 위계에서 나온다.

## 1. 기본 원칙

1. 한 문장에 한 사실을 쓴다.
2. 결론을 먼저 두고 근거를 뒤에 둔다.
3. 능동 동사를 쓰고 불필요한 명사화를 줄인다.
4. 수치, 날짜, 이름, 기관명은 입력에서 확인된 값만 쓴다.
5. 독자가 다음에 해야 할 일을 분명히 적는다.
6. 영문 직역체와 상투적 홍보 문구를 피한다.
7. 문서 전체에서 호칭, 시제, 숫자, 단위를 통일한다.

## 2. 문장 다듬기

| 피할 표현 | 권장 표현 |
|---|---|
| 검토를 진행했습니다 | 검토했습니다 |
| 개선을 수행했습니다 | 개선했습니다 |
| ~할 수 있도록 지원합니다 | ~하도록 돕습니다 |
| 혁신적인 솔루션 | 무엇을 어떻게 바꾸는지 구체적으로 |
| 최고의 경험 | 측정 가능한 결과 또는 사용자 반응 |
| 다양한 기능 | 실제 기능 2–3개 |
| 성공적으로 완료 | 완료 사실과 결과 |
| ~하는 것입니다 | ~합니다 |

접속사는 논리 관계가 필요할 때만 쓴다. “그리고”, “하지만”, “따라서”가 문장마다 반복되면 문단 구조를 다시 잡는다.

## 3. 제목

좋은 제목은 문서 종류와 핵심 주장을 함께 드러낸다.

```text
2026 상반기 제품 운영 보고서
지역 상점 재고 관리 제안서
결제 전환 개선 사례 포트폴리오
시드 투자 IR — 반복 업무를 줄이는 공간 운영 도구
```

“새로운 시작”, “더 나은 미래”, “혁신을 향하여”처럼 어느 문서에도 붙일 수 있는 제목을 피한다.

## 4. 문단

- 첫 문장은 결론 또는 문단의 역할을 밝힌다.
- 뒤 문장은 근거, 방법, 사례 순서로 쓴다.
- 한 문단은 보통 2–5문장으로 제한한다.
- 서로 다른 주장은 section 또는 bullet로 나눈다.
- 같은 내용을 제목, 요약, 본문에서 반복하지 않는다.

## 5. 목록

병렬 구조를 유지한다.

좋은 예:

```text
- 생성 시간을 40분에서 8분으로 줄였습니다.
- 승인 단계를 5개에서 3개로 단순화했습니다.
- 오류 발생 시 이전 상태로 복구하도록 만들었습니다.
```

나쁜 예:

```text
- 생성 시간 단축
- 승인이 간단합니다
- 오류 복구 기능을 개발한 경험
```

목록 항목이 한 단어로 끝나면 모두 명사형으로, 문장이면 모두 완결된 문장으로 맞춘다.

## 6. 숫자와 단위

- 천 단위 쉼표를 쓴다: `12,400원`.
- 숫자와 단위를 문서 전체에서 통일한다: `12%`, `3개월`, `₩24,000,000`.
- 비교 수치는 기준 기간을 함께 쓴다: `전월 대비 12% 증가`.
- 차트에는 단위, 기간, 표본, 출처를 남긴다.
- 제공되지 않은 수치를 계산하거나 그럴듯하게 만들지 않는다.
- “약”, “이상”, “최대”의 의미를 구분한다.

## 7. 이름과 전문용어

- 사람·회사·제품의 공식 표기를 유지한다.
- 기술명은 공식 영문 철자를 쓴다: `Next.js`, `TypeScript`.
- 처음 나오는 생소한 용어는 짧게 설명한다.
- 약어는 첫 등장에 전체 이름을 쓴다.
- 한자가 실제 고유명 구분에 필요한 경우에만 한글 바로 옆 괄호 안에 한 번 표기한다.
- 큰 장식 문자, 제목의 한자 병기, 의미 없는 전통 용어를 사용하지 않는다.

## 8. 문서별 톤

| 문서 | 톤 | 핵심 |
|---|---|---|
| 이력서 | 사실·성과 중심 | 행동, 범위, 결과 |
| 자기소개서 | 구체 사례 중심 | 상황, 판단, 행동, 배운 점 |
| 회사 소개서 | 짧고 자신 있게 | 존재 이유, 고객, 근거 |
| 제품 소개서 | 사용자 문제 중심 | 효용, 특징, 사양 |
| 제안서 | 상대 조직 중심 | 문제, 해결, 지표, 일정, 비용 |
| IR 덱 | 주장 중심 | 슬라이드당 한 주장과 근거 |
| 뉴스레터 | 친근하지만 정확하게 | 맥락, 소식, 다음 행동 |
| 보고서 | 중립적이고 검증 가능하게 | 현황, 결과, 이슈, 계획 |
| 청첩장·연하장 | 따뜻하고 짧게 | 이름, 날짜/인사, 보내는 이 |
| 포트폴리오 | 역할과 판단 중심 | 문제, 기여, 결과, 회고 |

## 9. AI 생성 시 사실 경계

다음은 추정하지 않는다.

- 연락처와 주소
- 경력·학력·자격
- 고객명과 매출
- 성장률과 시장 규모
- 수상·인증
- 일정과 비용
- 참석자·가족 정보

빠진 사실은 질문하거나 비어 있음을 명시한다. placeholder를 실제 값처럼 출력하지 않는다.
