# 한국어 이력서 작성 레퍼런스

삿갓 이력서는 A4 세로 기준의 사실 중심 문서다. 장식보다 채용 담당자가 빠르게 확인할 수 있는 경력·기여·결과를 우선한다.

## 1. 기본 구조

```text
이름 · 직무 제목
연락처 · 링크
두세 문장의 요약

경력
  회사 · 역할 · 기간
  핵심 기여와 결과 2–4개

기술
학력
선택: 프로젝트 · 발표 · 자격
```

필수 슬롯:

- `name`: 실제 사용하는 이름
- `title`: 지원 직무와 경력 수준
- `email` 또는 실제 연락 수단
- `summary`: 강점, 산업/문제 영역, 대표 결과
- `experiences`: 회사, 역할, 기간, 구체 기여
- `skills`: 실제 업무에 사용한 기술
- `education`: 학교·전공·기간 중 제공된 사실

사진, 생년월일, 가족관계, 주민등록번호, 상세 주소처럼 채용 판단에 불필요하거나 민감한 값은 기본으로 요구하지 않는다.

## 2. 요약 쓰기

요약은 2–3문장으로 끝낸다.

```text
7년차 프론트엔드 엔지니어. 커머스 결제와 검색 화면의 성능·접근성을 개선해 왔습니다.
디자인 시스템을 제품 조직에 도입하고, 반복 UI 개발 시간을 줄인 경험이 있습니다.
```

피할 문장:

- “열정적이고 책임감 있는 인재입니다.”
- “혁신적인 솔루션을 제공했습니다.”
- “다양한 업무를 성공적으로 수행했습니다.”

성격 형용사 대신 해결한 문제와 확인 가능한 결과를 쓴다.

## 3. 경력 bullet

한 bullet에는 하나의 사실과 결과만 둔다.

```text
동사 + 대상/문제 + 방법 + 결과
```

좋은 예:

- 결제 화면의 불필요한 JavaScript를 분리해 LCP를 3.1초에서 1.9초로 줄였습니다.
- 42개 공통 UI를 접근성 기준에 맞춰 통합하고 제품 5곳의 중복 구현을 제거했습니다.
- 오류 복구 흐름을 재설계해 결제 이탈률을 8% 낮췄습니다.

수치는 제공된 경우에만 쓴다. 정확한 수치가 없으면 “개선”, “단축”, “감소” 같은 방향을 쓰되 정도를 지어내지 않는다. 팀의 결과를 개인이 단독 달성한 것처럼 표현하지 않는다.

## 4. 기간과 순서

- 최근 경력부터 역순으로 배치한다.
- 기간 형식은 문서 전체에서 `2022.03–2025.06` 또는 `2022–2025` 중 하나로 통일한다.
- 재직 중은 `현재`로 쓴다.
- 공백 기간을 임의로 메우지 않는다.
- 같은 회사 안의 역할 변경은 회사 아래에서 역할별로 나눈다.

## 5. 기술

기술명만 나열하지 말고 채용 직무와 관련된 범주로 묶는다.

```text
언어        TypeScript · JavaScript
프레임워크  React · Next.js
품질        Testing Library · Playwright · 접근성 점검
협업        디자인 시스템 · 코드 리뷰 · 성능 예산
```

실제로 사용하지 않은 도구, 숙련도를 확인할 수 없는 별점·퍼센트, 유행 키워드를 넣지 않는다.

## 6. 프로젝트

경력만으로 대표 역량이 드러나지 않을 때 1–3개를 추가한다.

각 프로젝트:

1. 문제와 사용자를 한 줄로 설명한다.
2. 본인의 역할과 결정 범위를 밝힌다.
3. 구현보다 결과를 먼저 쓴다.
4. 공개 가능한 링크만 넣는다.

회사 기밀, 내부 URL, 고객 개인정보를 노출하지 않는다.

## 7. 한국어 표기

- 한 문장에 한 사실을 쓴다.
- 불필요한 명사화보다 능동 동사를 쓴다.
- 회사·학교·제품의 공식 표기를 보존한다.
- 한자가 실제 동명이인 구분 등 업무상 필요할 때만 한글 이름 바로 옆 괄호 안에 작게 표기한다.
- 큰 장식 문자, 도장 모티프, 섹션 제목의 한자 병기를 사용하지 않는다.
- 영문 기술명은 공식 철자를 쓰되 문장 구조는 자연스러운 한국어로 유지한다.

## 8. A4 조판

- 이름과 직무가 첫 3초 안에 보이게 한다.
- H1은 Nanum Myeongjo 700, 본문은 Gowun Batang 400을 사용한다.
- 본문은 약 10–11pt, 행간 1.7 이상을 시작점으로 삼는다.
- 경력 항목 사이에는 충분한 간격을 두고 bullet 안의 줄 간격은 일정하게 유지한다.
- 1쪽이 목표라면 관련성이 낮은 오래된 경력을 줄인다. 글씨를 작게 만들어 억지로 맞추지 않는다.
- 2쪽 이상이면 section 중간에서 페이지를 끊지 않고 각 페이지에 명확한 흐름을 둔다.

## 9. 사실 확인

생성 전에 확인할 값:

- 이름과 연락처
- 지원 직무
- 회사·역할·기간
- 대표 기여와 결과
- 기술과 학력
- 공개 링크

빠진 값은 사용자에게 요청한다. 이메일, 전화번호, 회사명, 학교, 수치, 수상, 자격을 추정하지 않는다.
